The model

A new frontier in doing more with much, much less

HomamadeLLM is an AI lab with a simple constraint: we do not have GPUs. Rather than treat this as a problem, we treat it as a research agenda. Every model we release is trained end to end on consumer CPUs, the kind already sitting in a backpack.

Shakespeare-Char is the first result of that program. It is a decoder-only transformer that reads text one character at a time and predicts the next one. After 2,000 training steps it has taught itself, from nothing, that plays have speaker names in capitals, that lines break like verse, and that English words are mostly made of English-looking syllables.

i.

CPU-native

Trained on two cores and four threads of a 2015 laptop processor. Inference runs anywhere PyTorch does.

ii.

Fully reproducible

Public-domain data, an MIT-licensed codebase, and one command. You can retrain it during a coffee break.

iii.

Small enough to understand

Four layers, four attention heads, a 65-character vocabulary. The whole model fits in your head and in an email attachment.

Evaluation

From random noise to almost-Shakespeare

Training starts at a loss of 4.17, which is exactly what you get by guessing uniformly among 65 characters. It ends at 1.89 on held-out text the model never saw. Train and validation stay close together, so the model is learning patterns rather than memorising the plays.

Quickstart

Run it in three steps

You need Python 3.9 or newer. No GPU, no account, no API key. The weights are published at huggingface.co/phuvey/shakespeare-char-nanogpt.

  1. Install the dependencies

    PyTorch runs the model, safetensors reads the weights, and huggingface_hub provides the hf download command.

    pip install torch safetensors huggingface_hub

  2. Download the model

    This fetches a few small files, including the weights, the config, the character vocabulary, and the model definition.

    hf download phuvey/shakespeare-char-nanogpt --local-dir shakespeare-char
cd shakespeare-char

  3. Generate text

    Save this as generate.py inside the downloaded folder and run python generate.py.

    import json, pickle, torch
from safetensors.torch import load_file
from model import GPT, GPTConfig

# Build the architecture from the config, then load the weights.
# strict=False: the output layer shares its weights with the embedding,
# so it is stored only once in the file.
model = GPT(GPTConfig(**json.load(open("config.json"))))
model.load_state_dict(load_file("model.safetensors"), strict=False)
model.eval()

# The tokenizer is just two lookup tables: character to id and back.
meta = pickle.load(open("meta.pkl", "rb"))
stoi, itos = meta["stoi"], meta["itos"]

prompt = "ROMEO:"
x = torch.tensor([[stoi[c] for c in prompt]])
y = model.generate(x, max_new_tokens=400, temperature=0.8, top_k=40)
print("".join(itos[i] for i in y[0].tolist()))

    Things to try: lower temperature to 0.5 for safer, more repetitive text, raise it to 1.2 for chaos. Change the prompt to any speaker name. The prompt can only contain the 65 characters the model knows: English letters, basic punctuation, spaces and newlines.

How we built it

Six steps, one laptop

The full pipeline, from raw text to a published model. Training uses nanoGPT by Andrej Karpathy, unmodified.

  1. Collect the data

    The corpus is tiny-shakespeare: 1,115,394 characters of Shakespeare's plays in a single text file, all in the public domain. The first 90% is used for training (1,003,854 characters) and the last 10% is held out for validation (111,540).

  2. Tokenize, one character at a time

    A language model works on numbers, not text. We use the simplest possible scheme: every distinct character in the corpus gets an integer id. There are 65 of them, so the vocabulary size is 65. No subwords, no byte-pair encoding. 

    python data/shakespeare_char/prepare.py

  3. Choose an architecture a CPU can afford

    A GPT-style decoder-only transformer, scaled down until it trains comfortably without a GPU. The model sees the previous 64 characters and outputs a probability for each of the 65 possible next ones.

    Layers4
    Attention heads4
    Embedding size128
    Context length64 characters
    Vocabulary65 characters
    Parameters804,096

  4. Train on the CPU

    Each step, the model reads 12 random excerpts of 64 characters, predicts every next character, and is scored with cross-entropy loss. The AdamW optimizer then nudges all 804,096 weights to do slightly better. Repeat 2,000 times: about 1.5 million characters seen in total, at roughly 55 milliseconds per step. 

    python train.py config/train_shakespeare_char.py --device=cpu --compile=False \
  --eval_iters=20 --block_size=64 --batch_size=12 \
  --n_layer=4 --n_head=4 --n_embd=128 \
  --max_iters=2000 --lr_decay_iters=2000 --dropout=0.0

    Hardware: Intel Core i5-6200U at 2.3 GHz, 7.5 GB of RAM, PyTorch CPU build.

  5. Export clean weights

    The training checkpoint also contains the optimizer state and is stored as a Python pickle, a format that can execute code when loaded. For release we keep only the model weights and save them as safetensors, which is plain data. The result is a 3.2 MB file plus a small config.json.

  6. Publish

    Weights, config, vocabulary and model code are uploaded to the Hugging Face Hub under the MIT license. 

    hf upload phuvey/shakespeare-char-nanogpt hf-export .

Responsible release

What it cannot do

We believe in being direct about limitations. There are several.

  • It does not make sense. The output has the shape of Shakespeare (speaker names, verse, archaic rhythm) but many words are invented and no sentence means anything.
  • It is not a chatbot. It continues text. It does not answer questions, follow instructions, or know what a question is.
  • It remembers 64 characters. Roughly one line of verse. Anything earlier is gone.
  • It knows 65 characters. A prompt containing anything else, such as digits or accented letters, raises an error.
  • It has one training run behind it. No hyperparameter search, no benchmark suite, one validation number.

The future of AI is compute-constrained. We got there first.
